# React Template 작업 팀 규약

## 목적과 패턴

이 저장소는 클라이언트 전역 주입, API 프록시, 서버 정적 제공과 배포 경로가 연결되어 있어 기본 패턴을 **순차 파이프라인 + 위험 기반 리뷰**로 둔다. 일반 작업은 한 에이전트가 끝까지 소유하고, 독립성이 명확한 읽기·리뷰 작업만 선택적으로 분리한다.

## 단계와 책임

| 단계 | 책임 | 입력 | 출력 |
| --- | --- | --- | --- |
| 요청 정리 | 목표, 범위, 완료 기준, 기존 변경 확인 | 사용자 요청, `git status` | 대화 요약 또는 `_workspace/01_request.md` |
| 설계 | 영향 범위와 교차 계층 계약 결정 | 요청, 구조 문서, 관련 코드 | 구현 계획 또는 `_workspace/02_design.md` |
| 구현 | 최소 변경으로 계약 전체 갱신 | 승인된 범위 | 소스·설정 변경 |
| 검증 | 정적 검사, 빌드, 실제 동작 확인 | 변경 diff | 명령 결과 또는 `_workspace/04_validation.md` |
| 리뷰 | 요구사항·운영 위험·누락 판정 | 원 요청, diff, 검증 증거 | `통과/수정 필요/재검토 필요` 또는 `_workspace/05_review.md` |

최종 통합과 완료 판정은 현재 작업을 맡은 주 에이전트가 소유한다.

## 작업 분리 기준

- 한 에이전트 유지: 한 기능의 UI·타입·API가 함께 바뀌는 작업, 라우트와 레이아웃 변경, 서버 미들웨어 순서 변경.
- 분리 가능: 클라이언트와 서버의 읽기 전용 영향 분석, 보안·배포 코드의 독립 리뷰, 서로 다른 화면의 브라우저 점검.
- 분리 금지: 같은 파일을 동시에 수정하는 작업, 같은 `dist`/`build`를 쓰는 병렬 빌드, 같은 포트나 PM2 프로세스를 공유하는 테스트.
- 작업을 분리하면 각 담당자의 파일·리소스 경계, 기대 산출물, 실패 시 보고 내용을 시작 전에 명시한다.

## 품질 게이트

1. 모든 코드 변경: `npm run verify`
2. Webpack·환경 주입·정적 자산·서버 번들 변경: `npm run build`
3. UI 변경: 대상 화면을 브라우저에서 직접 확인
4. 서버·프록시 변경: 실제 HTTP 경로, 상태 코드, 응답 본문 확인
5. 종료 전: `git diff --check`, `git status --short`

테스트 스위트가 생기면 루트 `verify`에 포함하고 이 문서와 `AGENTS.md`를 함께 갱신한다.

## 실패와 중단 처리

- lint, TypeScript, build 실패는 원인과 최초 오류를 남기고 수정 후 다시 실행한다.
- 외부 API, Redis, 인증서, Slack, GitHub, PM2 미구성은 환경 제약으로 분리해 보고한다.
- 위험한 운영 명령이나 배포 훅 검증은 개발용·격리 환경이 없으면 실행하지 않고 미검증 위험으로 남긴다.
- 리뷰가 `수정 필요`이면 한 차례 수정과 재검증을 수행한다. 같은 문제가 반복되거나 범위 확대가 필요하면 사용자에게 판단을 요청한다.
- 일부 단계가 실패해도 완료로 표시하지 않는다. 성공한 검사와 남은 검사를 구분해 전달한다.
